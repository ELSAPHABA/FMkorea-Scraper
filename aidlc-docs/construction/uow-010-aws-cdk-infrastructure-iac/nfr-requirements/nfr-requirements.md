# NFR Requirements - UOW-010 AWS CDK Infrastructure IaC

## Purpose

UOW-010 must provide a small, secure AWS CDK baseline for running scraper containers on AWS.

The baseline is intentionally not the future multi-community management platform. It defines reusable shared infrastructure and a reusable one-shot worker stack pattern that a later platform can call.

## Cost Requirements

- The default architecture must minimize idle cost.
- Worker execution must use ECS Fargate one-shot tasks, not always-on ECS services.
- NAT Gateway must not be created by default.
- Worker tasks may run in public subnets for outbound-only scraping.
- RDS defaults must stay small and environment-configurable.
- EventBridge schedules must be optional.
- CloudWatch retention must be configurable and short by default for non-production environments.
- Expensive production-grade features may be supported through environment configuration, but must not be forced on dev/staging.

## Availability And Recovery Requirements

- RDS PostgreSQL must be single-AZ by default for dev/staging.
- Production must support configurable Multi-AZ and longer backup retention.
- Stateful resources in production must use retention-oriented removal policies by default.
- Dev may use destructive removal policies only where the data is disposable.
- S3 outputs, failure records, reports, and media objects must not be lifecycle-deleted by default.
- Retry and replay workflows must be able to use preserved S3 outputs and failure records.

## Security Requirements

- Runtime secrets must be injected from AWS Secrets Manager.
- CDK source, environment config files, CloudFormation templates, logs, and generated docs must not contain plaintext secret values.
- CDK may create secret placeholders or reference existing secret names/ARNs.
- Secret auto-rotation is not required in this unit.
- RDS credentials may be generated by RDS/Secrets Manager or provided through operator-managed Secrets Manager values.
- Task roles must use least-privilege access scoped to the required environment bucket/prefix, required secrets, CloudWatch Logs, and required AWS service actions.
- S3 buckets must use server-side encryption by default.
- RDS must run in private subnets.
- Worker tasks must expose no inbound application ports by default.
- Security groups must allow worker-to-RDS access only on the PostgreSQL port.

## Data Retention Requirements

- S3 lifecycle rules must be disabled by default.
- Raw JSONL outputs, failure JSONL, reports, and retry inputs must be preserved unless an operator explicitly enables lifecycle rules.
- Media lifecycle policy may be added as an environment option later if storage cost becomes a measured problem.
- The object key strategy must remain compatible with existing scraper output contracts and later shared-platform prefixes.

## Observability Requirements

- Worker container stdout/stderr must be sent to CloudWatch Logs.
- Log group names and retention must be environment-aware.
- A basic ECS task failure alarm must be available by default.
- Dashboards and custom application metrics are deferred.
- Default observability must be enough to answer whether a one-shot task started, exited successfully, or failed.

## Configuration Requirements

- CDK must support `dev`, `staging`, and `prod`.
- Non-secret environment configuration should live in files such as `infra/cdk/config/{env}.yaml`, combined with CDK context where useful.
- Config files may contain secret names or ARNs, but not secret values.
- Worker stack inputs must include `site_id`, image URI/tag, command/env, optional schedule, and shared infrastructure references.
- The same worker stack pattern must be reusable for later scraper containers by changing inputs, not CDK internals.

## Verification Requirements

- The default verification gate must run `cdk synth`.
- Template-level unit or snapshot tests must verify expected resource categories and important security properties.
- The default gate must not require live AWS deploy/destroy access.
- Live deploy smoke tests are optional and belong to later operational validation.
- Synth output must be inspectable for at least S3, RDS PostgreSQL, ECS task definition, task role, CloudWatch log group, Secrets Manager references, and optional EventBridge schedule resources.

## Out Of Scope

- No EKS/Kubernetes deployment.
- No SQS job queue or worker registry in this unit.
- No centralized management dashboard.
- No AWS deployment of Garage or SeaweedFS.
- No scraper runtime behavior changes.
- No CAPTCHA bypass, request-rate policy change, parser change, or source-specific query logic.

## Acceptance Criteria

- NFR decisions match the approved UOW-010 Functional Design.
- CDK design can keep initial AWS cost low without blocking production hardening.
- Secrets are never represented as plaintext in source, config, template, or logs.
- Worker tasks can access S3, RDS, logs, and required secrets with scoped permissions.
- Production stateful resources are protected by default retention-oriented policies.
- The CDK app remains reusable by later scraper workers without introducing the future platform early.
